# Implementierungsvertrag Projektformat 1

Arbeitsvertrag für die erste testbare Projektverwaltung. Keine Live-Steuerung, keine aktiven Treiber. Alle unbekannten Mess-/Verbindungsparameter bleiben unbekannt.

Rootfelder: `format: "pohl-energy-project"`, `schema_version: 1`, `id`, `name`, `mode: "planning_only"`, Arrays `grids`, `areas`, `nodes`, `connections`, `devices`, `channels`, `measurements`, Objekt `settings` (versionierte JSON-Konfiguration, zunächst leer). IDs sind nichtleere stabile ASCII-Kennungen `[a-zA-Z0-9_-]{1,80}`, je Sammlung eindeutig; Namen nichtleere Texte max160 Zeichen. Rootfelder vollständig erforderlich. Nur die hier beschriebenen Felder zulassen, optionale Felder dürfen fehlen oder null sein. Grenzen: Datei2MB, max500 Objekte je Sammlung, max2000 insgesamt, begrenzte JSON-Tiefe; keine NaN/Infinity, doppelten JSON-Schlüssel oder Zugangsdaten.

- grids: erforderliche `id,name`.
- areas: erforderliche `id,name,grid_id`.
- nodes: erforderliche `id,name,grid_id,parent_id` (null an Wurzel). Eindeutiger kreisfreier elektrischer Baum je Grid mit genau einer Wurzel; gleiche Grid-ID entlang Elternkette.
- connections: erforderliche `id,name,kind`. kind: modbus_tcp, modbus_rtu_usb, modbus_tcp_rtu_gateway, rtu_over_tcp, mqtt, solarman, ha. Optional host,port,serial_port,baudrate,parity,stopbits. Keine Passwort-/Tokenfelder. Fehlende Endpunkte sind als Entwurf erlaubt, werden gewarnt. Keine aktive Verbindung beim Import.
- devices: erforderliche `id,name,kind,area_id,node_id`; kind: gateway,meter,pv_inverter,hybrid_inverter,storage_inverter,battery,ev_charger,heater. Optional connection_id,via_device_id,unit_id,parent_id,model,phases,capacity_kwh,max_power_kw,capabilities. capabilities: measure,switch,set_power. Gerätebereich und elektrischer Knoten müssen zum selben Grid gehören. Batterie parent_id muss vorhandenen WR bezeichnen (pv_inverter ausgeschlossen), gleiches Grid. Andere parent_id-Beziehungen derzeit nicht zulassen. via_device_id beschreibt unabhängig davon gateway oder WR, darf nicht kreisen und muss denselben connection_id nutzen wenn beide eine Verbindung angeben. Geräte-/Gateway-Kommunikation darf Bereichsgrenzen überschreiten. phases null/1/3, unit_id null/1..247, Zahlen endlich positiv; source-unbekannte Fähigkeiten mit [] führen.
- channels: erforderliche id,name,device_id,quantity,unit,source. quantity/unit: active_power W/kW, soc %, voltage V, current A, energy Wh/kWh, temperature °C, state bool. Optional phase null/L1/L2/L3/total. source erforderliches kind unconfigured/modbus/mqtt/ha; optional address,function_code,data_type,scale,topic,json_path,entity_id. Modbus hier nur Lesezuordnung FC03/04 mit dokumentierter Adresse0..65535, data_type u16/s16/u32/s32/float32, scale endlich ungleich0. MQTT topic und optional json_path, HA entity_id; unbekannte Quelle kind unconfigured. Keine erfundenen Register in Vorlage.
- measurements: erforderliche id,name,role,node_id,channel_id,includes_device_ids. role grid/branch/pv_generation/battery_power/consumer/load; Kanal muss active_power sein. Zugehörige Quelle kann über Gateway in anderem Bereich liegen; tatsächlicher Messknoten ist node_id. Pro Grid genau eine primäre grid-Messung an Wurzel, pro Node/role höchstens eine. Derselbe Kanal nicht mehrfach als primäre Messung nutzen. Enthaltene Geräte dürfen nicht zu fremdem Grid gehören.
- settings: JSON-Objekt für künftige Regeln/Tarife/Prognosen. In v1 keine Ausführung oder Optimierung daraus ableiten. Rekursiv Schlüssel password,passwd,token,access_token,refresh_token,api_key,secret,credentials sowie Steuerfreigaben enabled_control/actuator_enabled verbieten. Unbekannte Modi/Versionswerte ablehnen, nicht stillschweigend downgraden.

API Python core/project.py: validate_project(data)->tiefe Kopie, load_project_json(text)->dict, export_project_json(data)->str, project_summary(data)->dict mit counts und warnings. Keine stillen Änderungen gültiger Fachdaten. Fehler ValueError mit verständlichem Feldpfad. Funktional äquivalente JS-Prüfung in preview/project-model.js für offline UI. Gemeinsame Beispiele und Fehlerfälle für Parität verwenden.

Messquellgerät und Messknoten müssen denselben Netzanschluss haben; die Kommunikation darf über ein Gateway außerhalb des Bereichs führen. Enthaltene Geräte müssen im gemessenen elektrischen Teilbaum liegen. Integerfelder beziehen sich auf den Zahlenwert (z.B. 1.0 ist ganzzahlig), bool gilt nicht als Zahl. Host-/Portbezeichnungen sind Konfiguration ohne Erreichbarkeitsnachweis.

Erster Umfang: Erstellen einfacher Vorlage, anonymisiertes Referenzprojekt laden, Projekt-/Objektnamen bearbeiten, gesamte JSON-Konfiguration im Editor bearbeiten, Import prüfen/vorschauen/ausdrücklich übernehmen, Export, lokale Speicherung. Messorte/Verbindungen/Quellen getrennt anzeigen. Kein Livewert und kein angeblich optimierter Mehrspeicherplan aus dieser Konfiguration.
